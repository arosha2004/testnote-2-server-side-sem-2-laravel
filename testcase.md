# NoteHub API QA Test Cases Reference

This table registers the core API test cases across authentication, notes management, validation, and security testing.

| Test Case ID | Test Scenario | Test Steps | Prerequisites | Test Data | Expected/Intended Results | Actual Results | Test Status – Pass/Fail |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :---: |
| **TC-001** | User Registration API Testing | Open Postman &rarr; Select POST &rarr; Enter `/api/register` &rarr; Add JSON body &rarr; Click Send | Laravel server running | Name: John Doe, Email: john@gmail.com, Password: password | User account should be created and access token generated | API returned `201 Created` with access token and user details | **Pass** |
| **TC-002** | User Login API Testing | Open Postman &rarr; Select POST &rarr; Enter `/api/login` &rarr; Add login credentials &rarr; Click Send | Registered user account available | Email: john@gmail.com, Password: password | User should login successfully and receive Bearer token | API returned `200 OK` with access token and user information | **Pass** |
| **TC-003** | Create Note API Testing | Select POST &rarr; Enter `/api/notes` &rarr; Add Bearer Token &rarr; Enter note data &rarr; Click Send | User authenticated with Sanctum token | Title: Meeting Notes, Content: Project discussion details | New note should be created successfully | API returned `201 Created` with saved note details | **Pass** |
| **TC-004** | Display Notes API Testing | Select GET &rarr; Enter `/api/notes` &rarr; Add Bearer Token &rarr; Click Send | Notes already exist in database | Authorization Token | All user notes should be displayed successfully | API returned `200 OK` with notes list in JSON format | **Pass** |
| **TC-005** | Update Note API Testing | Select PUT &rarr; Enter `/api/notes/1` &rarr; Add Bearer Token &rarr; Update note content &rarr; Click Send | Existing note available | Updated title and content | Existing note should update successfully | API returned `200 OK` with updated note information | **Pass** |
| **TC-006** | Delete Note API Testing | Select DELETE &rarr; Enter `/api/notes/1` &rarr; Add Bearer Token &rarr; Click Send | Existing note available | Note ID: 1 | Selected note should be deleted successfully | API returned `204 No Content` and note removed from database | **Pass** |
| **TC-007** | Unauthorized Access Testing | Select GET &rarr; Enter `/api/notes` without token &rarr; Click Send | Protected API route available | No authentication token | Unauthorized users should be blocked | API returned `401 Unauthorized` message | **Pass** |
| **TC-008** | API Validation Error Testing | Select POST &rarr; Enter `/api/notes` &rarr; Leave required fields empty &rarr; Click Send | API validation rules configured | Empty request body | Validation errors should be displayed | API returned `422 Unprocessable Content` with validation error messages | **Pass** |
| **TC-009** | SQL Injection Security Testing | Select POST &rarr; Enter `/api/notes` &rarr; Insert SQL injection code into content field &rarr; Click Send | Authentication token available | `'; DROP TABLE notes; --` | Application should prevent SQL injection attack | Database remained secure and API handled request safely | **Pass** |
